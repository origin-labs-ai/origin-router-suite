# v0.6.000 (2026-11-09)

The 0.6 line: 24 routing strategies, a conversation fold layer, 140+ providers, and the router can hold a key back.

## Added
- **24 routing strategies.** The router grew from 4 strategies to 24. The new registry (`src/lib/routing/strategies.js`) adds the rotation family (strict-random deck draw, weighted, fill-first, power-of-two-choices, least-used, last-known-good), the cost/context/cache family (cost-optimized, context-optimized, cache-optimized, shadow-cache), the quota family (reset-aware, reset-window, headroom, quota-weighted, expiry-first — fail open to fairness rotation without a quota source), the adaptive family — **Auto** and **AutoAgressive**, which classifies the turn and tightens the switch bar when seats degrade — plus **Latency Arbitrage** (real-time cost × speed × health scoring per seat) and the **Pipeline** strategy: seats run in sequence, each stage's draft feeds the next, and the final seat answers with the drafts attached. Every orderer fails open and returns a permutation, so the fallback walk behind it can still reach every seat; a shared circuit breaker demotes (never removes) seats that fail repeatedly. Legacy names (`priority`, `usage`, `cheapest`, `max_utility`, …) normalize automatically.
- **OriginFold, the conversation fold layer.** When a conversation's token estimate crosses a fraction of the model's context window, OriginFold folds consumed history into tiered summary blocks and keeps a verbatim recent zone — append-only and suffix-only, so the upstream prompt-cache prefix is never invalidated. Reversibility instead of spillover: blocks restore on demand, search over summaries, and status are exposed as server-side tools (`compress_context`, `decompress_context`, `search_context`, `fold_status`) for the MCP/A2A surfaces. Every path fails open; tiny conversations are never touched. Runs before every other token saver.
- **142 providers.** 41 new OpenAI-compatible API-key providers curated from the OmniRoute v3.8.54 and Free Claude Code catalogs — DeepInfra, W&B Inference, Atlas Cloud, xKiro, Opper, NaraRoute, Experiential Labs, Cheaper Inference, OrcaRouter, Lightning AI, ZenMux, Z.ai, Kimi Code, Codestral, Alibaba Cloud ModelStudio, QwenCloud (Token Plan + Coding), Ollama Cloud, AI/ML API, Novita, ElectronHub, LLM Gateway, NanoGPT, Requesty, FriendliAI, Inference.net, Lambda, DigitalOcean GenAI, Nscale, Monster API, OVHcloud AI Endpoints, AI21, Writer, Segmind, Upstage Solar, Sarvam, Typhoon, SEA Lion, Qianfan, iFlyTek Spark, ModelScope — with the dead ones excluded (poolside shut down 2026-10-31, g4f proxies, web-cookie-only endpoints, special-auth enterprise clouds) and the exclusions documented inline.
- **Hand Picked OpenAI Compatible.** The user's own compatible endpoints get their own dashboard category, and every provider without an icon asset — hand-picked endpoints, imports from other routers, anything new — renders the letter glyph + deterministic accent color (`NexAPI` → **N**, `OrcaRouter` → **OR**, `Orca-Router` → **OR**, `Orca Route` → **OR**). Providers that have an icon keep using their icon.
- **The presets are Mythos / Revolt Deffusion / Auto Agressive / Select-your-own.** Mythos (formerly "Max") is everything maxed — the merged Jev+Panda brain with the smart router on top, compression ultra. Revolt Deffusion is the same brain at medium/full compression. **Auto Agressive** is the new fourth preset: the same merged brain on the AutoAgressive strategy — every turn is classified, seats switch eagerly and the confidence bar tightens to 0.6 when a seat degrades, the knobs the strategy moves itself. Select-your-own writes nothing behind the user's back. The old `max` id keeps resolving as an alias, and the wizard's strategy picker now lists all 24 strategies.
- **A shared circuit breaker + seat health stats.** Every seat outcome (pick, success, failure, latency) is recorded per combo, scores the orderers, and is readable via `getSeatStatsSnapshot()`. A seat that fails three times in a row is demoted to the back of the order for a 60s cooldown — demotion, never removal.
- **PandaOrchestrator local detection.** At boot the router looks for a local PandaOrchestrator install and reports exactly how to start it via the panda status API and one log line — the router reports, the user starts (it never spawns third-party binaries on its own). A found-but-stopped install no longer reads as a broken brain.
- **Revolt Fusion, the extension-pack architecture.** The base stays featherlight; heavy categories hydrate on demand into `<DATA_DIR>/fusion-modules/`, hash-verified against their manifest before a byte lands on disk, hot-loaded with the `webpackIgnore` dynamic-import pattern (no restart), and removable. The Get Started tiers — **Daily Code**, **Pro** (hand-pick categories), **MHHRSM**, and **Ultra Ultimate Max** (everything, every knob at its ceiling) — live on the new Fusion Setup page, next to the DB manager: every table categorized (core / features / analytics) with the three data-retention presets (minimal / standard / full), prune and vacuum.
- **Provider Adapter Harness + reasoning state preservation.** Three thin adapters (openai / anthropic / gemini) behind a `complete()` contract for the deterministic surfaces, and a reasoning replay cache (LRU 200 / 2h, ≤20 blocks per request) that re-attaches captured `reasoning_content` where the same tool_call id reappears — strict thinking-mode upstreams stop rejecting follow-up turns.
- **A general MCP server.** `POST /api/mcp` speaks JSON-RPC 2.0 (initialize / tools/list / tools/call / ping) and exposes six router tools: list_models, routing_plan (deterministic, side-effect free), memory_stats, strategy_list, fold_stats, harness_list.
- **A2A protocol surface.** Agent Card at `/.well-known/agent.json`, JSON-RPC task lifecycle (message/send, tasks/get, tasks/cancel, tasks/stats) with a bounded task manager (500 tasks, 24h TTL) and the smart-routing skill executing the real routing plan.
- **Mid-stream recovery.** The FCC DeliveredPrefix/ContinuationSeed concept, native: a delivery tracker snapshots what the client already received (text, reasoning, tool-call fragments, 1 MB cap), and `buildContinuation` rebuilds the next seat's request so a dead stream CONTINUES instead of repeating.
- **A compression engine registry with gates.** Engines are plugins ordered by stack priority; the lossless pair (session-dedup, lite) ships built-in behind a fidelity gate (structural rollback on violation), a risk gate that shields credential-shaped spans, and per-model exclusions. The lossy engines join via the fusion pack only after their eval harnesses pass.
- **Local Models.** A new dashboard page: live Ollama / LM Studio / llama.cpp engine probes, unified Hugging Face + Ollama-library search with source tags, one-click pull/download with progress and cancel (argv-array spawns, never shell), and a "+ Add model file" registration for existing .gguf / .safetensors / .bin files.
- **The provider graveyard, documented.** [docs/PROVIDER-GRAVEYARD.md](docs/PROVIDER-GRAVEYARD.md) records per provider in the reference catalogs whether it is alive, shut down (with dates), web-cookie-only, special-auth, or unverified — dead and expired providers are excluded from the registry and the exclusions travel with the id.
- **OriginFold persistence + search.** Fold sessions now survive a restart (file-backed store under `<DATA_DIR>/fold/`), and `search_context` scores blocks with BM25-lite term weighting instead of substring matching.
- **Memory Fabric.** An opt-in persistent shared context layer: remember/recall/forget with scope keys, hit counting, and a prompt-injection seam — coding agents share one memory loop without resending context.
- **Shadow Cache.** An encrypted local response cache for temperature=0 requests: AES-256-GCM at rest, LRU-backed, per-request bypass header, temperature/stream/tools guards.
- **Cloud Sync — Google Drive, the one option.** Sign in with Google in the wizard's Cloud sync step; backups land in Drive's appDataFolder with credentials redacted (keys never leave the machine), restore merges the non-credential parts back.
- **Migration sources grew to five.** Other router installs, OmniRoute, Free Claude Code, **9Router** (full connection/combo/settings import through the shared SQLite dialect) and **OpenCode CLI** (provider definitions with api keys from its opencode.json — registry-mapped or as compatible nodes).
- **Settings resets.** The profile page's Danger zone: restore-default Claude Code config (backup-restore or surgical key removal — unrelated settings never touched) and a scoped factory reset (backup-first, API keys always survive, `RESET` typed to confirm).
- **Skills pipeline.** The code-fusion payloads catalog (952 skills) imports with the CONFLICT.md merge policy — existing wins, internal duplicates first-by-name wins, conflicts recorded with both sides. Skills are data: hashed and copied, never executed. Scan → review → install on the Skills page.
- **A test gate in CI.** The suite (4,400+ tests) now runs on every push and PR (`test.yml`), `npm test` is wired at the root, the tests package got real scripts, the suite README is written, and the global test timeout is hardened against cold-cache flakes.
- **Per-key budgets.** Every API key can carry its own requests per minute, tokens per minute, tokens per day and a cap on how many of its requests run at the same time. The check happens in the gateway before a single token is spent upstream, and a key that spent its allowance gets a `429` with `Retry-After` and `X-RateLimit-*` headers. A limit of 0 means "no limit", so a key without a budget is never slowed down. The budgets live on *Endpoint & Key → API Keys → Limits*.
- **A provider health dashboard.** Every provider is graded live — healthy, degraded, down or idle — with the request count, the error rate, the average and the p95 latency and the last error it produced. It is on the usage page next to the cost forecast.
- **Request replay.** Any logged request can be sent again from the request log, with the original endpoint and body, so a failure can be reproduced and a good answer regenerated.
- **A cost forecast.** What today, the last 7 days and the last 30 days cost, what the month will cost if the current pace holds, how much of the traffic was free and which providers spent it.
- **A first-run wizard.** The Get Started wizard asks for a theme, offers the keys of any other router on this machine, walks through the first provider and the first combo, and wires Claude Code in one click. Every step can be skipped on its own or skipped as a whole.
- **A native Claude Code setup.** One button writes the whole `~/.claude/settings.json`: the endpoint, the user's own API key, the models, the model picker, the effort level and the timeouts. The file it replaces is kept as a backup. The CLI tools page and the wizard now share one implementation.
- **A data folder and a start mode for the portable build.** The portable build asks two questions of its own, first because they matter most: where the data is stored (default `~/.or`) and whether the app starts in the tray.

## Fixed
- **The installer added the install folder to the user PATH again on every update**, so a machine that was updated a few times carried a dozen copies of the same entry. The PATH is now rewritten with exactly one copy, and the existing copies are cleaned up on the next install.
- **The install scripts could not install anything when npm was unreachable.** `install.ps1` fell back to a release lookup against the retired repository name, so the fallback was a 404. Both scripts now use the current repository, verify the SHA256 before they run anything, and `install.sh` falls back to the portable build when npm is not there at all.
- **The README described a startup entry that does not exist.** The installer writes a registry Run key, not a `.vbs` file in the startup folder. The README now says what actually happens.
- **Provider icons 404'd for every SVG/ICO provider.** Icon resolution guessed `.png` for all of them, so a provider whose logo shipped as `.svg` or `.ico` (aimlapi, zenmux, lambda, …) fell back to a letter glyph even though its logo was on disk. A generated manifest (`npm run gen:icons`, wired into `predev`/`prebuild`) now maps 277 ids to the format that actually exists, and the component only walks the extension ladder for ids the manifest has never seen.
- **The setup wizard never closed.** `Finish` skipped stamping `onboardingComplete` whenever a migration had run, so the dashboard immediately redirected back into the wizard — the popup that would not close. `/api/migrations` takes `complete: true` to stamp the flag without re-running an import, and the dashboard reads the flag per request (`force-dynamic`) instead of pinning a build-time decision.
- **`Next` was a silent no-op on steps that carry a choice.** It now stays disabled with "Select an option to continue." until the step is actually answered; `Skip this step` and `Skip setup` still work everywhere.
- **Every popup sat inside a hover transform.** A transform makes the card the containing block for its fixed descendants, so menus and popovers slid with the card's 2px hover lift and jumped back when the cursor left. Cards now opt out of the lift while they hold an open popup, and tooltips re-measure after layout settles instead of freezing coordinates captured mid-transition.
- **The test workflow was red for every run.** `cache: npm` needs a lockfile this repo deliberately does not commit; with that fixed the job then hit npm 10's arborist crash on vitest 4's peer graph, and finally five tests that assumed a Windows host (plus a missing `ffmpeg`). All four layers are fixed and the ubuntu job is green.
- **Hidden providers.** `hidden: true` never removed a provider from the routing table — it only hid the card — and `trae`/`windsurf`/`devin-cli` were removed from the registry index entirely. Ten were un-hidden (bluesminds, sambanova, mmf, iflow, gitlab, mimo-free, cartesia, coqui, playht, tortoise, plus the TTS shelf on the media lists); `trae` and `windsurf` are enabled; `devin-cli` stays behind an explicit opt-in switch because its executor spawns a local agent with shell access, and `/v1` refuses it with `403 local_executor_disabled` while the switch is off.
- **Skills showed the literal string `>-`.** Folded YAML frontmatter (`description: >-`) was parsed as the marker itself, so the Skills cards and the injected system prompt carried `>-` instead of the description. Folded and literal block scalars parse now, and the prompt block leads each line with the skill's invocable command.

## Changed
- **npm is out of the install path.** The package `@origin-labs-ai/origin-router` was never published — every `npm install -g` and every `npx` command in the docs, the landing page, both install scripts and the updater pointed at a 404. Installation is now only the release installer (Windows) and the one-line scripts; the dashboard's update button installs `OriginRouter-Setup-<version>.exe` from the release feed with its `.sha256` verified instead of running `npm i -g`; the relaunch-after-update command is the installed launcher rather than `npx`. Registry-publish scripts, npm badges and the "package not found" troubleshooting entry are gone, and the docs site carries the installer commands. `npm` stays what it is: the development toolchain (`npm install`, `npm run build`, `npm test`).
- **Media Providers is gone as a section.** It was a second navigation tree — sidebar accordion, a listing page per kind, a per-provider detail route — for providers that are, in the end, just providers. The Providers page now renders one section per media kind (embedding, text to image, image to text, TTS, STT, web search, web fetch, video, system one) with its count and `/v1` endpoint, cards open the same provider page as everything else, and the per-kind example/test panels moved onto that page so nothing was lost. The `/api/media-providers/*` endpoints stay — `/v1/audio/voices` proxies them.
- **The wizard's close control is the macOS traffic light** shared with every modal: a red dot that shows its cross on hover, then two ring-only dots. The Settings page gained a **Setup wizard** card so the flow can be re-run on demand.

# v0.5.116 (2026-11-06)

Docker boot fix, API-key hardening, architecture docs that describe reality — and the two failures that kept this cut from shipping. Full working log: [docs/RELEASE-LOG.md](docs/RELEASE-LOG.md).

## Fixes
- **The Docker image answered 403 to its own host.** Inside a container the host's traffic to a published port is NAT-ed to the container's default gateway, and the LAN gate read that address as "another device on the network" — so `docker run -p 20128:20128` was unusable, the dashboard could not be opened to switch LAN access on, and the CI smoke test failed on both architectures. A new `src/lib/containerNetwork.js` resolves the container's default route from `/proc/net/route` and counts that one address as "this computer"; LAN devices keep their real IP and stay blocked. The lookup only runs when the image sets `OR_CONTAINER=1`. Covered by `tests/unit/container-network.test.js`.
- **The Windows release ran out of disk** (`ENOSPC` after 1h47m). The job carried a redundant root `npm run build`, the CLI build's own `.next-cli-build` tree and the root `node_modules` — none of which ship, because the installer only packages `cli/app` → `dist/win`. The job now builds the CLI bundle once and reclaims ~3.2 GB before packaging; it also prints free space so the next disk failure is visible.
- **Docker boot fix.** v0.5.115's GHCR images built for both architectures but died on startup — the standalone bundle ships `next/dist/server` code that imports `@swc/helpers` subpaths at runtime, file tracing omits the package, the health check never came up, and manifest publishing skipped. The Dockerfile now copies `@swc/helpers` + `@next/env` into the runner stage (same explicit-copy pattern already used for `next`, `sql.js` and `node-machine-id`).
- **API keys minted with real randomness + per-install secret.** `keyId` went from 6 `Math.random()` chars (~31 bits, predictable) to 16 `crypto.randomInt` chars (~2^83); the HMAC integrity digest uses `API_KEY_SECRET` if set, else an auto-generated secret persisted at `DATA_DIR/api-key-secret` (0600), instead of a constant baked into the source tree. Existing keys stay valid — request auth is an exact match against the `apiKeys` table; the digest is integrity-only.
- **`docs/ARCHITECTURE.md` describes the current storage model** — state and usage live in `${DATA_DIR}/db/data.sqlite` (default `DATA_DIR` is `~/.or`), not the doc's old `~/.originrouter` JSON files; the per-install API-key secret file is documented too.

## Changed
- **Release notes ship with the release.** `release.yml` picks up curated notes from `docs/releases/<tag>.md` when they exist, and falls back to the generated changelog when they do not.
- In-range dependency updates: undici 7.30.2, eslint-config-next 16.4.5. Major bumps deferred deliberately — a release cut is the wrong time to take chalk 6 / undici 8 / eslint 10 / better-sqlite3 13.

# v0.5.117 — origin-router, the README, and the links that pointed at the wrong project

A naming-and-truth release. The product works; this cut makes the product's
**name**, its **links** and its **documentation** match the product.

## Changed

### The package is `origin-router`

The npm identity of the launcher is now **`@origin-labs-ai/origin-router`** and the
published tarball is `origin-router-<version>.tgz`.

The unscoped name `origin-router` on the npm registry belongs to an unrelated
package published in 2014 (`bstow`, an HTTP URL router, last release 2022), so it
cannot be claimed. The scope carries the product name exactly — `origin-router` —
and puts the package under the organisation that owns it. The GitHub repository
slug stays `origin-labs-ai/origin-router-suite`: GitHub retired the shorter name
for this organisation (`name has been retired and cannot be reused`), so a
rename there is refused by the platform, not by permissions.

Everything that referenced the old identity now points at the new one — the
installer script, the npm commands in the docs, the launcher, the updater's
package constant, and the tarball name the release workflow produces and
checksums.

### The Docker image is `origin-router`

`ghcr.io/origin-labs-ai/origin-router` — the image name was derived from the
repository slug, so it was published as `.../origin-router-suite` while every
document said `.../origin-router`. The name is now explicit in the workflow:
the image is named after the product.

### The landing page pointed at somebody else's project

Eleven GitHub links, two npm links and the copy-command in the landing page
still pointed at a different repository. A visitor clicking **GitHub** or
**Docs** on the product page was taken away from the product. All of
them now point at this project, and the npm link at the scoped package.

The same block also claimed the data lives in `~/.originrouter/db/data.sqlite`
and `%APPDATA%/originrouter/...`. It does not: state lives in `~/.or`
(`src/lib/dataDir.js`), and the landing page now says so. The copyright year
was 2025.

### The product has a link preview now

A bare GitHub link posted to a chat, a forum or a feed used to preview as
nothing. `public/og-image.png` is a 1200×630 card rendered from the real
dashboard (`scripts/make-og-image.js`), and `src/app/layout.js` now declares the
Open Graph and Twitter card metadata that use it.

### The README tells the whole story

Rewritten around OriginRouter itself: the routing brain and what its three
signals actually are, the four combo strategies with what each costs, the token
saver with the measured numbers, the installer, the CLI, the desktop app and
Docker, the endpoints, and a table of **what OriginRouter changed against
upstream originrouter v0.5.112** — including the parts that are *not* differentiators,
so the README never claims an upstream feature as ours.

`docs/FORK.md` holds the full file-by-file comparison.

### Screenshots in both themes

The Providers, Combos and Token Saver pages, captured in light and dark, in
`images/`.

### The Windows installer no longer needs npm

`install.ps1` installs the npm package when it is available and falls back to
the GitHub release installer when it is not — the one-liner works either way.

  `<scope>-<name>-<version>.tgz`; the asset is renamed to `origin-router-<version>.tgz`
  before it is checksummed and uploaded.
- `tests/README.md` was still titled "OriginRouter Embeddings Tests".
